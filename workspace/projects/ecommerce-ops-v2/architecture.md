# 电商运营数字员工 v2 — 技术架构

## 1. 架构总览

采用 **任务工厂** 模式：任务定义（配置）与任务执行（运行）分离，
以 **SQLite 数据库为核心** 支撑配置、运行、审计、复核全链路。

```
┌─────────────────────────────────────────────────────────────┐
│                        CLI / 调度入口                        │
│            python main.py run / schedule / review           │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│                      执行引擎 (runner)                       │
│   ┌─────────────┐ ┌─────────────┐ ┌─────────────┐          │
│   │ 订单核对任务 │ │ 库存对账任务 │ │ 商品清洗任务 │  ...可扩展 │
│   └──────┬──────┘ └──────┬──────┘ └──────┬──────┘          │
│          └───────────────┼────────────────┘                 │
│                   任务注册表 (registry)                      │
└───────────┬───────────────────────────────────┬─────────────┘
            │                                   │
┌───────────▼────────────┐        ┌─────────────▼─────────────┐
│      数据层 (loader)    │        │     SQLite 数据库 (db)     │
│   读原始数据/写结果      │◄──────►│  tasks/runs/audit/reviews │
└────────────────────────┘        └───────────────────────────┘
            │
┌───────────▼────────────┐
│   规则引擎 (rules)      │   强规则定义，可配置参数
│   + AI 分析扩展点       │   (预留异常智能分析接口)
└────────────────────────┘
```

## 2. 分层设计

### 2.1 db/ — 数据层
- `db.py`：SQLite 连接管理、建表、初始化
- `models.py`：数据模型常量与表结构定义
- 核心表：
  - `tasks`：任务定义（类型、参数JSON、调度、启停、复核策略）
  - `task_runs`：每次执行记录（状态、异常数、耗时、结果路径）
  - `audit_logs`：审计日志（全部操作留痕）
  - `reviews`：人工复核记录（通过/修改/驳回）

### 2.2 agent/ — 业务层
- `registry.py`：任务类型注册表（可插拔）
- `tasks/`：具体任务实现（订单核对、库存对账、商品清洗）
- `rules.py`：强规则定义与校验
- `runner.py`：执行引擎（调度、重试、结果落库）
- `audit.py`：审计记录
- `loader.py`：数据接入（读 CSV 原始数据）
- `report.py`：日报生成

### 2.3 main.py — 入口
CLI 命令：`run` / `schedule` / `review` / `history` / `audit` / `init-db`

## 3. 数据模型 (SQLite)

见 `db/models.py`，核心表 ER 关系：

```
tasks 1 ──── * task_runs
task_runs 1 ──── * audit_logs
task_runs 1 ──── 0..1 reviews
```

- `tasks`：任务配置中心（"任务工厂"的核心）
- `task_runs`：每次执行快照（可追溯、可复核）
- `audit_logs`：全量操作审计（信任兜底）
- `reviews`：人工复核（关键操作强制确认）

## 4. 技术选型（遵循"不重复造轮子"）

| 组件 | 选择 | 理由 |
|------|------|------|
| 数据库 | SQLite | 本地优先、零部署、足够承载 MVP |
| 数据处理 | pandas | 成熟、电商数据清洗标配 |
| 调度 | 内置 schedule 循环 | MVP 不引入 APScheduler，避免过度工程化 |
| AI 增强 | 预留接口 | MVP 用强规则，AI 异常分析作为 v2.1 扩展 |
| 测试 | pytest | 轻量、标准 |

> 说明：遵循"快速验证优先""不做重复造轮子"原则，本 MVP 不引入
> LangGraph/Dify/Chroma 等重型组件。当任务需要 AI 判断时，通过
> `rules.py` 预留的 AI 分析扩展点接入（可复用 Personal AI OS 能力）。

## 5. 扩展点

- **任务注册表**：新增任务只需实现 `BaseTask` 子类并注册
- **AI 分析**：`rules.py` 预留 `ai_analyze()` 接口，可接入 DeepSeek
- **数据源**：`loader.py` 预留 API 接入（当前从 CSV 读取）
