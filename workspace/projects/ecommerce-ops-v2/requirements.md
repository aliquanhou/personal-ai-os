# 电商运营数字员工 v2 — 需求文档

## 1. 背景与定位

基于 **"任务工厂"** 理念（从"岗位"转向"任务"），本 v2 版本聚焦电商运营中
**高重复、强规则、可量化 ROI、低信任成本** 的具体任务，而非泛化的"岗位替代"。

**核心定位**：一个能自主、持续、不出错地执行**具体电商运营任务**的数字员工。
结果交人工复核，关键操作强制确认（信任兜底）。

### 与 v1 的差异

| 维度 | v1 (ecommerce-ops-agent) | v2 (本版本) |
|------|--------------------------|-------------|
| 设计哲学 | 岗位导向（一个 agent 做多件事） | 任务导向（一个任务一个可配置执行单元） |
| 数据存储 | 文件 + 轻量 SQLite | **SQLite 为核心数据库**，任务/运行/审计/复核全面结构化 |
| 配置方式 | 代码硬编码规则 | **任务配置化**（任务定义 + 规则参数入库） |
| 人工复核 | 无 | **复核台**：一键通过/修改/驳回，关键操作强制确认 |
| AI 增强 | 仅规则 | 预留 AI 异常分析扩展点 |

## 2. 目标用户

- 电商中小商家 / 代运营团队
- 有大量重复性运营任务（订单核对、库存对账、数据清洗、日报生成）

## 3. 核心功能需求

### 3.1 任务配置（Task Config）
- 每个任务有独立定义：类型、规则参数、调度频率、复核策略
- 支持任务启停

### 3.2 任务执行（Task Runner）
- 按任务定义执行具体运营任务
- 全程留痕（审计日志）
- 失败重试 + 出错自愈
- 结果写入数据库

### 3.3 人工复核台（Review）
- 对关键操作结果进行人工确认（通过/修改/驳回）
- 强制确认策略（高风险任务必须人工复核）

### 3.4 报表与审计（Report & Audit）
- 自动生成运营日报
- 所有操作可追溯

## 4. MVP 任务范围

首批落地 3 个强规则任务（可量化 ROI）：

1. **订单核对** — 检测重复订单、无效平台、无效状态、异常金额
2. **库存对账** — 系统库存 vs 仓库库存，检测差异与负数库存
3. **商品资料清洗** — 标准化商品数据，计算毛利率，标记异常

> 不做：复杂客服、销售成交、战略决策（低规则强度，信任成本高）

## 5. 非功能需求

- **技术栈**：Python 3.10+、SQLite、pandas、pytest
- **可扩展**：任务类型可插拔，AI 异常分析预留接口
- **可追溯**：每笔操作有审计记录
- **本地优先**：数据本地存储，可私有化部署

## 6. 验收标准

1. 数据库模型可初始化，含任务/运行/审计/复核四类核心表
2. 三个 MVP 任务可执行，结果正确写入库
3. 测试通过（pytest）
4. 运行报告可生成
